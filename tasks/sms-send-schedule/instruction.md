Harbor & Pine Home Goods, Inc., a home goods retailer, has a batch of promotional text messages scheduled to go out, and marketing operations must review every one of them before launch. For each message the team has to decide whether to send it at its scheduled time, move it to the earliest later minute at which it is allowed to go out, or not send it at all. The only rule that governs these decisions is the FCC's rule at 47 CFR 64.1200, as published in the eCFR and amended through 90 FR 42138 (August 29, 2025), and the company has no internal policy that adds anything beyond it.

All of the input files are in /app/data/. The file /app/data/scheduled_messages.csv lists the batch, giving each message's message_id, contact_id, campaign_id, platform_id and its scheduled_at time in UTC. The file /app/data/contacts.csv holds each recipient's phone number and the city, state and IANA time zone of their mailing address. The file /app/data/area_codes.csv is the carrier's area code table and is there for reference only. The file /app/data/platforms.csv describes the two sending platforms and the equipment each one uses. The file /app/data/campaigns.csv lists the campaigns, and every message in the batch is promotional. The file /app/data/consents.csv holds the consent records the company has collected, broken out into their elements: whether the consent is in writing, the type of signature, the seller named in it, the phone number covered, the two disclosures, and where the record came from. The file /app/data/replies.csv contains the text replies received from recipients. The file /app/data/seller_dnc_requests.csv contains do-not-call requests that recipients made to the retailer through other channels. The file /app/data/national_dnc_matches.csv gives, for numbers found on the national do-not-call registry, the time each was registered and the time the registration was cancelled, if it was. The file /app/data/customer_history.csv records purchases, inquiries and applications along with the date of each. The file /app/data/seller.json gives the seller's legal name and lists its affiliates. Every timestamp in the data is in UTC, and the dates in the customer history are plain calendar dates without a time.

Each part of the rule reaches a different set of messages. Prior express written consent is required for a message sent using equipment that is an automatic telephone dialing system, and you must decide which platform that is from the equipment descriptions in the platform file. The seller's own do-not-call obligations apply to every promotional message in the batch, whatever consent or relationship the recipient has with the seller. The national do-not-call registry protections and the restriction on calling hours apply to messages that are telephone solicitations as the rule defines that term. Only a consent record that meets the rule's definition of prior express written consent counts as the recipient's prior express invitation or permission.

The rule leaves some choices open, and for this task they are fixed as follows. A reply revokes consent when it is one of the words the rule treats as revoking per se, in any letter case and with any surrounding punctuation, or when it is an unambiguous and explicit request to stop receiving messages. A complaint, a vague expression of not being interested, or a request that depends on some condition is not a revocation. Every do-not-call request, whether it arrives as a revoking reply or appears in the request file, also revokes consent. It takes effect at the moment it is received, and it ends any business relationship that existed at that moment. Consent that has been revoked never comes back. The seller's do-not-call obligation lasts for the period the rule sets, counted from the exact UTC time of the request, and sending is allowed again starting from that exact minute. You can rely on the data containing no new consent, purchase or inquiry after any do-not-call request. A national registration counts from its registration time until its cancellation time, and you should ignore the registry safe harbor provisions entirely.

A recipient's local time is determined by the time zone of their mailing address, and every recipient should be treated as a residential mobile subscriber. Both the first minute and the last minute of the allowed calling window count as allowed. When the rule looks back a number of months from a date, the period starts on the same day number that many calendar months earlier, or on the last day of that earlier month if that day number does not exist in it. The date the look-back is measured from is the recipient's local date at the moment the message would be sent. Each message is decided on its own, and moving one message has no effect on any other. A message that cannot go out at its scheduled time is rescheduled to the earliest compliant time within seven days after its scheduled time, and blocked if there is none. Some of those earliest compliant times fall exactly at the point where a recipient's status changes, so the timing is exact to the minute.

Write your answer to /app/output/send_schedule.csv. Its first line must be exactly message_id,decision,send_at and it must then contain one row for every message, in the same order as /app/data/scheduled_messages.csv. The decision column must be SEND, RESCHEDULE or BLOCK, written in capitals. The send_at column must use the form 2026-10-29T15:00:00Z, in UTC with the seconds always 00. For SEND it is the scheduled time, for RESCHEDULE it is the new time, and for BLOCK it is left empty. Do not add extra columns, comments or blank lines, because every row is compared exactly.

You have 28800 seconds to complete this task. Do not cheat by using online solutions or hints specific to this task.
